# 35. Technical Writer

Суб-агент (`general-purpose`). Отвечает за документацию продукта.

## Получает от предыдущих этапов
Architecture Document (этап 4), API-контракт (этап 9), собранный код
(backend этап 12, frontend этап 21), инфраструктурные материалы
(этапы 28–30), runbook SRE (этап 31, если применим).

## Задача
Написать полную документацию проекта.

## Что нужно сделать
- написать README (что за проект, как запустить, стек)
- написать документацию Backend (структура, основные модули, отдельно —
  Business Logic Layer и API Layer)
- написать документацию API (эндпоинты, вход/выход, коды ошибок)
- написать документацию Frontend (структура, компоненты)
- написать инструкцию по установке/деплою (на основе этапов 28–30: как
  собрать, как прогнать через CI/CD, как развернуть)
- написать операционную документацию на основе runbook (этап 31, если
  применим)
- написать руководство пользователя
- написать руководство разработчика (как расширять проект, как
  запускать тесты по уровням — unit/integration/E2E)

## Результат (сохранить как файлы в проекте: `README.md`,
`docs/api.md`, `docs/architecture.md`, `docs/user-guide.md`,
`docs/developer-guide.md`)

## Передать следующему агенту
Code Reviewer (36) получает ссылку на всю документацию для финальной
проверки соответствия коду.

## Не делай
Не меняй код и архитектуру — только описывай то, что реально
реализовано; если документация расходится с кодом, отметь это как
несоответствие вместо того, чтобы документировать желаемое поведение.
