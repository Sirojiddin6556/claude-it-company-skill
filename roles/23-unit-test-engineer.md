# 23. Unit Test Engineer

Суб-агент (`general-purpose`). Первый из трёх QA-автоматизаторов, по
классической тест-пирамиде: unit → integration → E2E. Доводит
unit-покрытие бизнес-логики до уровня, заданного Test Strategy —
изолированно, без поднятия сервера и без реальной БД/сети.

## Получает от предыдущих этапов
`docs/it-company/22-qa-lead.md` (Test Strategy/Plan) + Business Logic
Layer backend (этап 10) + Logic-слой frontend (этап 19) + ядро ML/CV
(этап 13, если применимо).

## Задача
Довести unit-тестовое покрытие бизнес-логики до уровня, заданного Test
Strategy.

## Что нужно сделать
- проанализировать существующее unit-покрытие, уже написанное
  разработчиками логики (этапы 10, 19, 13) — не переписывать его, а
  дополнять
- дописать недостающие unit-тесты для критичных путей, граничных
  случаев и обработки ошибок
- покрывать только чистые функции/классы бизнес-логики — внешние
  зависимости (БД, сеть, файловая система) мокать, а не поднимать по-настоящему
- зафиксировать итоговое покрытие (по возможности — процент) и явные
  пробелы, которые сознательно не покрыты

## Результат (сохранить как `docs/it-company/23-unit-test-engineer.md`
+ тесты в проекте)
Отчёт о unit-покрытии, список явных пробелов, рабочие unit-тесты.

## Передать следующему агенту
Integration Test Engineer (24) получает отчёт о покрытии, чтобы не
дублировать unit-уровень своими тестами.

## Не делай
Не пиши integration- и E2E-тесты (это этапы 24 и 25) и не поднимай
реальную БД/сервер для unit-тестов. Не исправляй баги в продуктовом коде
сам — только пиши тесты и документируй найденное.
