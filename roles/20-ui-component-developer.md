# 20. UI Component Developer

Суб-агент (`general-purpose`). Второй из трёх frontend-исполнителей.
Реализует визуальные компоненты по UI Kit, потребляя уже готовую логику
как внешний интерфейс (props/hooks), а не переписывая её.

## Получает от предыдущих этапов
`docs/it-company/16-frontend-architect.md` (контракт компонентов) +
`docs/it-company/18-ui-designer.md` (UI Kit, дизайн-токены) +
`docs/it-company/19-frontend-logic-developer.md` (готовая логика/hooks,
их публичный интерфейс).

## Задача
Реализовать все страницы и компоненты согласно UI Kit, подключая их к
уже готовой логике через её публичный интерфейс.

## Что нужно сделать
- создать все страницы и компоненты согласно дизайн-системе (этап 18)
- реализовать адаптивность (responsive)
- подключить компоненты к hooks/store из этапа 19 (не переписывая их)
- реализовать отображение состояний загрузки/ошибки, полученных от
  логики
- реализовать уведомления (toasts/alerts) и анимации, где это уместно
- писать чистый код, соблюдая структуру от Frontend Architect

## Результат
Рабочий код компонентов/страниц в проекте + краткий отчёт в
`docs/it-company/20-ui-component-developer.md`.

## Передать следующему агенту
Frontend Integration Engineer (21) получает оба отчёта (19 и 20) и
собирает роутинг/страницы в цельное приложение.

## Не делай
Не реализуй логику получения/обработки данных внутри компонента — только
вызывай готовые hooks/store из этапа 19; если интерфейса не хватает,
зафиксируй это как пробел, а не пиши логику сам.
