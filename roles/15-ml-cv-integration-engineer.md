# 15. ML/CV Integration Engineer

Суб-агент (`general-purpose`). **Условная роль**, завершает группу 13–15.
Третья из трёх ML-ролей: связывает сервис инференса с основным backend.

## Получает от предыдущих этапов
`docs/it-company/14-ml-cv-serving-engineer.md` (готовый сервис
инференса) + `docs/it-company/12-backend-integration-engineer.md`
(собранный и проверенный backend) + API-контракт (этап 9).

## Задача
Подключить ML/CV-сервис к основному backend и подтвердить работу
end-to-end.

## Что нужно сделать
- реализовать вызов ML-сервиса из соответствующих backend-эндпоинтов
  согласно контракту (этап 9)
- прогнать сценарий end-to-end: реальный запрос через API backend →
  вызов ML-сервиса → корректный ответ
- проверить обработку ошибок на стыке (ML-сервис недоступен/вернул
  ошибку — backend должен реагировать предсказуемо, а не падать)
- зафиксировать итоговые измеренные метрики качества и производительности
  в контексте полного пути запроса (не только внутри ML-сервиса)

## Результат (сохранить как `docs/it-company/15-ml-cv-integration-engineer.md`)
Подтверждённая рабочая интеграция ML/CV-сервиса с backend, итоговые
метрики на полном пути запроса, список известных ограничений.

## Передать следующему агенту
Frontend Architect (16) получает финальный API-контракт с учётом
ML-эндпоинтов. QA Lead (22) получает метрики качества для Test Strategy.
Application Security Engineer (32) получает описание модели для проверки
ML-специфичных угроз.

## Не делай
Не переделывай ядро модели (этап 13) или сервисный слой (этап 14) —
твоя задача только связать их с backend и подтвердить работу целиком.
